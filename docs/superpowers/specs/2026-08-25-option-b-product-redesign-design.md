# 带上方案 B 产品改造设计

日期：2026-08-25

## 1. 改造目标

将现有“模板 → 创建本次清单 → 完成 → 历史 → 决定是否写回模板”的流程，改成已经确认的方案 B：用户直接选择场景并开始勾选，平时只关注清单；需要维护内容时才进入“整理”。

产品只解决一个核心问题：出门前快速想起需要携带的物品。第一版不增加登录、智能推荐、出发时间、标签、完成页和历史记录。

## 2. 核心业务对象

### 场景

场景代表一次可重复使用的出门情境，例如“周末旅行”“商务出差”。场景独立存在，可绑定多个分区，并保存分区顺序。

### 分区

分区是清单中的轻量段落，例如“证件”“数码”“衣物”。分区独立存在，可被多个场景复用。

### 物品

物品是唯一的全局对象，例如“身份证”“充电器”。物品独立存在，可以同时绑定多个分区；第一版只维护名称，避免数量、备注等字段干扰快速使用。

### 绑定关系

- 场景与分区：多对多，场景侧有显示顺序。
- 分区与物品：多对多。
- 场景与物品勾选状态：按场景独立保存。

同一物品即使通过多个分区进入同一场景，也只显示一次。显示位置取该场景中最靠前、且包含该物品的分区。

## 3. 用户流程

### 清单首页

- 默认展示所有场景卡片。
- 卡片显示场景名称、物品数和当前已勾选数。
- 点击场景直接进入清单，不再创建“本次清单”。
- 可在首页新建场景。

### 场景清单

- 按场景绑定的分区顺序展示物品。
- 点击物品直接勾选或取消勾选，并自动保存。
- 顶部显示完成进度。
- “添加物品”支持搜索已有物品；已有物品直接复用，不重复创建。
- “重新准备”清空该场景的勾选状态。
- 全部勾选后仅显示 3 秒轻提示，不进入完成页面。

### 整理

底部导航只有“清单”和“整理”。整理页包含两个内部标签：

- 分区：新建、编辑、删除分区，并选择该分区出现在哪些场景。
- 物品：搜索、新建、编辑、删除物品，并选择绑定到哪些分区。

未绑定物品只用角落中的小圆点和数量提示，不弹窗、不阻断主流程。

### 编辑场景

- 修改场景名称。
- 选择使用哪些分区。
- 调整场景内分区显示顺序。
- 删除场景时不删除分区和物品。

### 删除规则

- 删除场景：只删除场景及其绑定和勾选状态。
- 删除分区：物品保留；没有其他分区的物品变为未绑定。
- 删除物品：删除其所有分区绑定和场景勾选状态。
- 所有删除操作均二次确认。

## 4. 前端设计

Vue 前端替换旧的模板、本次清单、完成和历史主流程，使用以下页面结构：

- `/`：清单首页。
- `/scenes/:id`：场景清单。
- `/organize`：整理页，分区/物品切换。

场景、分区和物品编辑使用底部操作面板，保持手机端单手操作。页面继续使用现有 Vue、Vue Router 和原有视觉变量，不新增大型 UI 依赖。

旧路由不再出现在界面入口中，必要时统一跳转到首页，避免旧链接显示废弃流程。

## 5. 后端设计

Spring Boot/MyBatis 后端新增规范化数据表：

- `scene`：场景。
- `packing_section`：分区。
- `packing_item`：物品。
- `scene_section`：场景与分区关系及排序。
- `section_item`：分区与物品关系。
- `scene_item_state`：场景物品勾选状态。

接口按资源拆分：

- `/api/scenes`：场景增删改查、获取场景清单、重置勾选状态。
- `/api/sections`：分区增删改查和场景绑定。
- `/api/items`：物品搜索、增删改查和分区绑定。
- `/api/scenes/{sceneId}/items/{itemId}/checked`：更新勾选状态。

服务层负责事务、名称唯一性、绑定合法性、排序整理以及场景内物品去重。前端不自行拼装跨资源关系。

## 6. 旧数据迁移

现有 H2 数据库不会被直接删除。

- `scene_template` 中的模板转换为新场景。
- 同名分区按去除首尾空格、忽略大小写后的名称合并。
- 同名物品按相同规则合并。
- 根据原模板结构生成场景—分区、分区—物品关系。
- 旧 `packing_list` 和原表继续保留作为备份，新版页面不再读取。
- 迁移需要可重复执行，通过迁移标记避免重复导入。

## 7. 异常与反馈

- 同名场景、分区或物品返回明确提示，不静默创建重复数据。
- 删除仍被绑定的对象时，由后端按既定删除规则清理关系。
- 接口错误在当前页面以轻量提示展示，用户可以重试。
- 保存按钮防止重复提交，勾选操作采用即时反馈并在失败时恢复。

## 8. 验收标准

- 新用户打开后能直接理解“选一个场景开始勾选”。
- 场景、分区、物品都能独立新建和编辑。
- 场景与分区、分区与物品的多对多绑定真实持久化。
- 同一物品绑定多个分区后，在同一场景中不重复显示。
- 修改共享分区的物品后，所有绑定该分区的场景自动生效。
- 勾选进度刷新页面后仍保留，“重新准备”可清空。
- 未绑定物品提示不打断清单使用。
- 手机宽度和桌面浏览器均可正常操作。
- 后端测试、前端构建通过。

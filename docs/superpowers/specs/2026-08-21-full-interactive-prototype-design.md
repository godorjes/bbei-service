# 带上：完整可交互 HTML 原型设计

日期：2026-08-21

## 1. 目标

把现有的局部演示重做为一个可以完整体验产品逻辑的手机端 HTML 原型。它首先解决一个问题：用户出门前能够立即打开对应清单，照着逐项确认，不必每次重新回忆需要携带什么。

原型必须适合第一次使用的人，不依赖说明书；同时能够容纳三四十件以上的长清单，但不能引入标签、全局物品库或多级分类等复杂概念。

## 2. 产品原则

1. 首页只回答“这次要检查哪张清单”。
2. 打开清单后，主要操作只有勾选和添加物品。
3. 分区只是当前清单内部的视觉区块，用于折叠和快速定位，不是全局分类。
4. 新增清单和新增物品都不要求用户先配置分区。
5. 低频管理操作收进菜单，避免干扰日常使用。
6. 所有显示出来的按钮都必须真实可用，不保留占位按钮或演示提示。

## 3. 范围

### 包含

- 三张可真实打开的示例清单：周末出游、商务出差、一周旅行。
- 新建、改名和删除清单。
- 查看清单的总数、已勾选数和完成进度。
- 勾选或取消勾选物品。
- 按“全部 / 未勾选”筛选物品。
- 新增、改名、移动和删除物品。
- 新增、改名、调整顺序、折叠和删除分区。
- 分区快速跳转。
- 清空一张清单的全部勾选状态。
- 浏览器本地持久化。

### 不包含

- 登录、注册和多端同步。
- 出发时间、提醒和日历。
- 系统推荐、智能补全和 AI。
- 标签、全局物品库和跨清单自动归类。
- 历史行程、“本次准备”和完成庆祝页。
- 后端接口、Vue 工程化和正式数据库。

## 4. 信息结构与页面

原型只有两个主页面，其他操作使用底部弹层或确认弹窗完成。

### 4.1 首页

- 顶部显示产品名“带上”和一句直接说明。
- 清单卡片显示清单名称、已勾选数、物品总数和分区数。
- 点击卡片主体进入对应清单。
- 卡片右侧的更多按钮用于改名和删除，不能触发进入清单。
- 页面底部提供“新增清单”。
- 当所有清单都被删除时显示空状态，并保留醒目的“新增清单”入口。

### 4.2 清单页

- 顶部提供返回、清单名称和更多菜单。
- 进度区域显示“已勾选 / 总数”和进度条。
- “全部 / 未勾选”用于临时筛选，进入清单时默认显示全部。
- 分区导航横向滚动，点击后跳到对应分区。
- 分区标题可以折叠或展开，右侧“＋”直接向该分区添加物品。
- 点击物品主体切换勾选状态。
- 物品右侧更多按钮打开“改名 / 移动分区 / 删除”。
- 底部固定“添加物品”按钮；从这里进入时默认选择上一次使用的分区，首次使用默认选择第一个分区。

### 4.3 清单设置

- 修改清单名称。
- 管理分区。
- 清空全部勾选。
- 删除当前清单。

### 4.4 分区管理

- 列出分区名称和物品数量。
- 提供改名、上移、下移和删除。
- 使用明确的上移/下移按钮，不使用看似可拖动但实际不稳定的拖拽手柄。
- 至少保留一个分区。
- 删除含有物品的分区时，确认文案必须写明接收物品的目标分区。确认后，物品移动到当前排序中的下一个分区；若没有下一个分区则移动到上一个分区。删除分区不会删除物品。
- 只剩一个分区时禁用删除，并说明“每张清单至少需要一个分区”。

## 5. 新用户与创建流程

### 新建清单

1. 用户点击“新增清单”。
2. 只输入清单名称，例如“露营”。
3. 系统创建清单并自动提供一个名为“物品”的默认分区。
4. 创建成功后直接进入空清单，页面突出显示“添加第一个物品”。

用户不需要理解或创建分区，就能完成第一次使用。

### 新增物品

1. 输入物品名称。
2. 分区已有默认值，用户可以直接保存。
3. 同一张清单内不允许出现忽略空格和大小写后重名的物品。
4. 保存后回到清单并显示新增物品所在分区。

## 6. 数据模型

本地存储的顶层结构为：

```text
AppData
  version
  scenes[]
    id
    name
    createdAt
    updatedAt
    sections[]
      id
      name
      items[]
        id
        name
        checked
        createdAt
```

约束：

- 每张清单至少有一个分区。
- 每件物品只属于当前清单中的一个分区。
- 分区不能跨清单共享。
- 标签不存在，也不会影响物品归属。
- 数量和进度始终根据当前数据实时计算，不保存重复的统计字段。
- 筛选条件、当前页面和弹层状态属于临时界面状态，不写入本地存储。
- 勾选状态写入本地存储，刷新后继续保留；用户通过“清空全部勾选”开始下一次检查。

## 7. 技术结构

交付一个独立 HTML 文件，CSS、初始数据和 JavaScript 全部内联。文件通过 `file://` 双击打开和通过本地 HTTP 服务打开时都必须工作，不引用外部模块、字体、图标库或网络资源。

JavaScript 在同一文件中按职责划分：

- `Seed`：生成首次打开时的三张示例清单。
- `Storage`：读取、校验和保存本地数据。
- `Model`：提供所有纯数据操作和业务约束。
- `View`：根据状态渲染首页、清单和弹层。
- `Controller`：统一处理点击、提交、返回和弹窗事件。

每次有效修改都遵循同一条数据流：

```text
用户操作 → Model 校验并生成新数据 → Storage 保存 → View 重新渲染 → 显示简短结果反馈
```

## 8. 反馈与异常处理

- 输入为空、名称重复或目标不存在时，在当前弹层中显示明确错误，不关闭弹层。
- 删除清单、删除物品、删除含物品的分区和清空勾选均需要二次确认。
- 普通成功反馈最多显示约 2 秒，不占据页面长期空间。
- 本地数据缺失时加载示例数据。
- 本地数据格式损坏时保留损坏数据的备份键，然后恢复示例数据并提示一次。
- 浏览器禁止本地存储时，原型继续在当前页面内可用，同时提示“刷新后可能丢失修改”。
- 空清单、空分区和“未勾选已全部完成”都提供明确空状态和下一步入口。

## 9. 视觉与交互约束

- 继续使用当前温和的米白与绿色视觉语言，但减少解释性文字。
- 手机内容宽度最大 430px，桌面浏览时居中显示。
- 主要触控区域不小于 44px。
- 不依赖长按、悬停或隐藏手势完成关键操作。
- 弹层打开后焦点进入第一个输入框；关闭后返回原触发位置。
- 支持键盘操作、可见焦点和基础 ARIA 标签。
- 尊重系统“减少动态效果”设置。

## 10. 验收标准

1. 三张示例清单均能进入，并显示各自独立且准确的数据。
2. 新建清单后无需创建分区即可添加第一个物品。
3. 清单、分区和物品的新增、改名、移动、排序与删除均真实生效。
4. 首页统计、清单统计、分区统计和进度条在每次修改后同步更新。
5. 刷新页面或重新打开文件后，所有内容和勾选状态保持不变。
6. 清空勾选只改变勾选状态，不删除物品或分区。
7. 删除分区不会意外删除其中的物品。
8. 所有危险操作都需要确认，取消后数据保持不变。
9. `file://` 环境下没有模块加载错误、网络请求或控制台运行时错误。
10. 页面上不存在只弹出“功能未完成”提示的占位控件。

## 11. 验证方式

- 对数据模型逐项验证：创建、重名校验、改名、移动、排序、删除、清空勾选和统计。
- 在浏览器中走完三个关键路径：首次打开、创建并编辑清单、刷新后继续使用。
- 检查每个可见按钮的实际结果以及取消确认后的数据完整性。
- 分别通过本地 HTTP 地址和直接打开 HTML 文件验证。
- 检查窄屏、430px 手机宽度和桌面居中布局。
- 最终检查浏览器控制台，确保没有错误或失败的资源请求。
